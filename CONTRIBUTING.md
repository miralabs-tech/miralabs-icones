# Contributing to Miralabs Icônes

📖 [README](./README.md) · [Français](./README.fr.md)

## 🧬 How a symbol is described

A symbol is a set of **layers** in `src/data.ts`; the twelve variants (6 weights × 2 shapes) and the two tones are derived from them.

| Layer | Outline | Fill | Hierarchical |
| --- | --- | --- | --- |
| `p` primary glyph | stroke | stroke, or cut out of `e` (`cut`), or kept on top (`keep`, halo) | primary |
| `e` envelope | stroke | filled | faded (42 %) |
| `c` lines to cut | stroke | cut out of `e` | follows `e` |
| `f` always filled | filled | filled | primary |
| `h` hole | cut out of `f` | cut out of `e` and `f` | — |
| `pf` filled glyph path | — | filled (`"="` = close `p`) | — |

Six weights are six stroke widths aligned with `font-weight` (200 → 700: 1 → 2.4).

Between the source and the engines sits an **IR** (`src/ir.ts`): one symbol × one shape = a list of operations `{ kind: fill|stroke, d, w: [k, c], cut }`. The web engine (`src/render.ts`) turns it into SVG with masks; the native engine (`native/mira_symbols.h`, C99) rasterises it into a coverage mask.

## ✏️ Adding or fixing a symbol

1. Add one entry to `src/data.ts`, **at the end of `SYMBOLS`** (font codepoints are assigned in order): SF-style name, tags (French synonyms, what people type in search), layers. Helpers: `circle`, `rr`, `txt`.
2. Drawing rules: 24 grid, optical margins ≈ 3, 1.5 stroke, arcs over free curves, points on the half grid (x.5) for a sharp render at 12 px. A dot is a stroke of length 0.01 (it grows with the weight). Eyes, letters and inner lines go in `c`.
3. Brand names go in tags only, never in a symbol name ([LICENSE-BRANDS](./LICENSE-BRANDS)).
4. Run `bun run build` (it includes `codegen`), check the symbol in the explorer (`bun run dev`, outline × fill × 6 weights), then `bun test`. A changed drawing updates its geometry snapshot: `bun test test/geometry.test.ts -u`.
5. A new symbol or collection changes the counts in `test/api.test.ts`, `test/build.test.ts`, both READMEs (text, badge, collections table). Regenerate the preview with `bun scripts/preview.ts` if its selection changes.

The JS identifier of a symbol comes from its name (`square.and.arrow.up` → `squareAndArrowUp`); a reserved word gets a `_` prefix (`2g` → `_2g`, `return` → `_return`).

## 🗂️ Layout

```
src/data.ts            the source: layers, tags, collections (hand-edited)
src/ir.ts              render IR: symbolOps(sym, shape), the engines' contract
src/render.ts          web engine (~1 kB): symbolTree / symbolToString / symbolToElement
src/mira-symbol.ts     <mira-symbol> web component (light DOM, tree-shakable registry); .all.ts = whole set
src/types.ts           public type contracts (SymbolData, SymbolOptions, SymbolOp…)
src/names.ts           GENERATED by scripts/codegen.ts: SymbolName / SymbolCollection / SymbolWeight unions
scripts/build.ts       build runner: codegen, tsc (declarations) and bun build (JS) in parallel, then build-core
scripts/build-core.ts  pure generation: metadata/symbols/ir.json, esm/*, index.d.ts, sprites, font css, C header
scripts/font.ts        `--font` step (stroke → outline → woff2, optional dependencies)
scripts/preview.ts     renders docs/preview.png for the README
test/                  bun test (geometry audit through resvg included); test/browser/ = same audit in Chromium, opt-in
native/                mira_symbols.h (C99, nanosvg) + generated data + CMake + demo
adapters/              React, Vue, Svelte, Angular wrappers
docs/index.html        static explorer (GitHub Pages), imports dist/data.js and dist/render.js
dist/                  generated by `bun run build`, committed so the package works without a build
```

## 🏗️ Build outputs (`bun run build`)

- `data.js`, `ir.js`, `render.js`, `mira-symbol.js`, `mira-symbol.all.js`: direct transpilation of `src/*.ts` (`bun build --no-bundle`); matching `.d.ts` from `tsc` (declarations only).
- `index.d.ts`: types only, plus one typed constant per symbol (`trash: SymbolData & { name: "trash" }`). It declares no value that `esm/index.js` does not export at runtime.
- `symbols.json`: the complete, neutral data (paths, layers, tags, collections), what a non-JS engine reads.
- `ir.json`: paint operations for every symbol × shape, one line per symbol.
- `metadata.json`: no paths; for search, Figma plugin, autocompletion.
- `esm/<name>.js` + `esm/index.js`: one module per symbol, native tree-shaking.
- `sprite/<weight>-<shape>.svg`: 12 `<symbol>` sprites for `<use>`.
- `font/codepoints.json` + `font/mira-symbols.css`; `--font` adds `.ttf`/`.woff2` (glyphs are strokes, the outline conversion is derived and lossy).
- `--static`: `svg/<weight>/<shape>/<name>.svg`, 12 × 436 files.
- `native/mira_symbols_data.h`: the IR as C arrays.

The `svg/` tree and font binaries are neither committed nor exported by the package; they ship as release artifacts.

## ⌨️ Commands

| Command | What it does |
| --- | --- |
| `bun run build` | full build |
| `bun run build:static` | + `dist/svg/**` |
| `bun run build:font` | + `dist/font/mira-symbols.{ttf,woff2}` |
| `bun run build:check` | writes nothing, fails on drift (generated files, `dist/*.js`, `dist/*.d.ts`, orphans) |
| `bun run codegen` / `codegen:check` | regenerate / check `src/names.ts` |
| `bun run typecheck` | `src/` (isolatedDeclarations) + tooling |
| `bun run typecheck:dist` | compile a consumer against `dist/*.d.ts` |
| `bun test` | unit and geometry suite |
| `bun run test:browser` | geometry suite in Chromium (Playwright), opt-in |
| `bun run dev` | explorer with rebuild on change and live reload (`--port`, `--static`) |

CI runs `bun test`, both typechecks, `codegen:check` and `build:check`; run them before opening a pull request.

## 🚢 Releasing

1. Bump `version` in `package.json` on `main` (through a pull request), with `dist/` rebuilt.
2. Actions → **Release** → Run workflow, with the same version (without the `v`).
3. The workflow replays the gates, publishes to npm through trusted publishing (no token, provenance attested), then creates the `v<version>` tag and the GitHub release with the four archives.

The npm trusted publisher is bound to `.github/workflows/release.yml` and the `npm` environment: renaming either breaks the publish until npmjs.com is updated.
